# 正式试点上线与训练效果验收

> 定位：这份文档是“能否让真实团队开始使用”和“训练是否真的有效”的唯一上线口径。
> 原则：代码健康、数据齐备、模型收益是三件独立的事，不能用其中一项替代另外两项。

## 1. 当前阶段结论

平台已经具备受控试点所需的软件能力：邮箱登录、服务端 RBAC、双评与裁决、Holdout 隔离、硬检查、数据授权校验、版本冻结、ZIP 导出、审计链、自动备份、恢复演练、健康巡检和固定版本发布。

公网已经切换到独立试点空间 `wecraft-pilot`，演示账号已停用，`DEMO_SEED_IF_EMPTY=0`。但“正式全面投入使用”仍需要业务数据、真实盲测和书面签收。当前不应把演示数据或功能冒烟等同于真实训练收益。

| 层级 | 进入条件 | 当前状态 |
| --- | --- | --- |
| 技术可试用 | 公网 HTTPS、登录、数据库、备份、恢复演练和核心流程通过 | 已具备；告警、异地复制和异地恢复演练已闭环，共享主机隔离仍为风险 |
| 受控试点 | 真实团队账号、授权证据、数据责任人和试点范围明确 | 试点空间已建立，但独立账号和业务数据仍为 0 |
| 正式生产 | 真实数据量达标、Holdout 实验完成、收益与风险经业务签收 | 未完成，不得宣称全面上线 |

当前可复核状态、逐项负责人和关闭命令见[正式投用切换清单](production-cutover.md)。

## 2. 上线前必须通过的门禁

### A. 技术与运维

- [x] `https://wecraft-training.zer-go.cn/api/v1/health` 返回 `200`、`ok: true`、`database: "ok"`，revision 与本次发布一致。
- [ ] `/login` 返回 `200`，OWNER、评审人、AI 工程三类账号均可登录（当前只有 OWNER）。
- [x] 当天数据库备份存在、SHA-256 校验通过，并已从异地副本完成一次隔离库恢复演练。
- [x] `wecraft-training-backup.timer` 和 `wecraft-training-monitor.timer` 均为 `active`，最近一次巡检成功。
- [x] 训练平台 Caddy 路由存在；生产发布后重新确认，不存在时不得接收试点流量。
- [ ] 训练平台与 WeCraft 生产已使用独立 Docker daemon，或双方发布由共享锁串行且有值守；未满足时禁止同时构建。
- [x] 飞书告警 webhook 已配置并完成一次测试消息；`last-alert-test` 为 `result=ok`。
- [x] 异地备份已配置并验证可读取；`last-offsite-copy` 为 `result=ok`，并从 OSS 完成异地恢复演练。

### B. 数据与授权

- [ ] 优质案例 30–36 个，9 个主型各至少 3 个，其中目标值为每型 4 个。
- [ ] 已批准反例 10–20 个。
- [ ] 黄金 Brief 60–100 个。
- [ ] 每个进入训练集的案例均完成双评；分歧有裁决记录。
- [ ] 每个进入训练集的案例授权证据为 `VERIFIED`，且明确覆盖训练用途。
- [ ] Holdout Brief、候选和证据在实验关闭前不对普通评审暴露。
- [ ] 训练集、评测集分开，Holdout 不得进入训练导出。

以上数据量在仪表盘“正式试点数据门禁”中会显示缺口；该门禁只衡量业务数据，不替代技术、告警或签收。

### C. 训练实验

- [ ] 实验开始前登记假设、模型版本、提示词、解码参数、随机种子、数据版本和评审规则。
- [ ] B0（基线模型）与 B1（使用训练数据/机制提示的模型）使用同一批 Holdout Brief、同一模型底座和同一生成参数。
- [ ] 每个 pair 由 3 名独立评审盲评；评审人不得看到模型名、版本、来源或上一轮分数。
- [ ] 评审人不得是候选制作人；裁决人不得兼任同组评审。
- [ ] 主指标为成对盲测胜率；同时记录六维评分、硬检查失败率、生成耗时和单稿成本。
- [ ] 至少 30 个有效 Holdout pair；预先登记排除规则，禁止看到结果后改指标。
- [ ] 使用成对 bootstrap 计算 95% 置信区间；只有胜率置信区间下界高于 50%，且硬检查失败率没有恶化，才可称为“试点中观察到收益”。
- [ ] 置信区间跨过 50% 或样本不足时，结论必须是“尚不能证明有效”，不得用平均分或单个案例替代。

### D. 业务与合规

- [ ] OWNER 明确试点范围、不可用场景、数据保留期和删除流程。
- [ ] 授权证据、案例、候选、审计日志的保留期限和责任人已书面确认。
- [ ] 发生授权撤回、法律冻结或数据泄露时的升级联系人和 SLA 已确认。
- [ ] 设计负责人、法务/授权负责人、业务签收人完成书面验收。
- [ ] 上线公告明确：平台是数据生产与评审系统，不自动训练、不自动发布到 WeCraft 生产端。

## 3. 标准发布步骤

### 3.1 预检

```bash
ssh <training-host>
cd /opt/wecraft-training
cat /var/lib/wecraft-training/last-release
curl -fsS https://wecraft-training.zer-go.cn/api/v1/health
systemctl list-timers 'wecraft-training-*' --all --no-pager
bash scripts/ops/preflight.sh
```

确认没有其他发布构建占用主机。训练发布与 WeCraft 生产发布共用 Docker daemon 和 `/run/wecraft-release.lock`。

### 3.2 备份与发布

将已验证源码同步到 `/opt/wecraft-training` 后执行：

```bash
cd /opt/wecraft-training
bash scripts/ops/release.sh <immutable-revision-tag>
```

脚本会执行：获取共享发布锁、检查 `.env` 权限、创建数据库备份、构建固定版本镜像、校验镜像 revision、切换应用、等待健康、校验公网健康、revision、登录页和 Caddy 路由。

正常结果应包含 `RELEASE_OK`。任何一步失败都不得继续 smoke 或对外宣布上线。

发布完成后执行正式试点门禁：

```bash
cd /opt/wecraft-training
bash scripts/ops/preflight.sh --pilot
```

`runtime` 检查必须为 0 个阻断；`--pilot` 还应检查告警送达、异地副本、恢复演练来源、正式角色覆盖、数据量、训练授权、双评和三名评审的 Holdout。数据或外部凭据未完成时，不要用演示数据填充门禁。

### 3.3 功能冒烟

至少由两个人分别完成：

1. OWNER 登录，打开仪表盘和成员页。
2. ANNOTATOR 新建或打开一个案例，确认 375px 截图和沙箱 HTML。
3. AI_ENGINEER 对候选运行 HC-01 至 HC-05，确认无 ERROR。
4. 两名评审分别提交同一个 Holdout pair，确认彼此不可见。
5. 裁决人完成裁决，关闭实验。
6. 创建并校验 TRAIN 数据集，确认缺少授权的案例被阻断。
7. OWNER 批准并导出，下载 ZIP 校验 JSONL、CSV、manifest 和审计记录。
8. VIEWER 验证只读和越权请求被拒绝。

### 3.4 失败处理

- 应用无法启动：保留日志和数据库，不要反复重建；使用上一固定版本镜像回滚应用。
- 数据库迁移失败：停止切换，先用备份在隔离库复现；禁止 `prisma migrate reset`。
- Caddy 路由缺失：重新追加 `deploy/training/Caddyfile.snippet`，校验配置后重启 Caddy。
- 数据授权或 Holdout 异常：立即停止导出并冻结相关数据集，通知 OWNER 和授权负责人。

## 4. 训练效果如何验收

### 4.1 先定义“有效”

上线前由 OWNER、DESIGN_LEAD 和 AI_ENGINEER 共同签字确认：B0/B1 的定义、Holdout 数据版本、评审人数、主指标、排除规则和停止条件。实验开始后不得因结果不理想而改主指标。

### 4.2 试点实验记录

| 字段 | 必须记录 |
| --- | --- |
| 数据 | 数据集编号、版本、manifest hash、Holdout 版本 |
| 模型 | 供应商、模型名、版本、提示词版本、解码参数、seed |
| 评审 | 评审人、盲法、pair 数、每人评分量、裁决记录 |
| 指标 | 胜率、95% CI、TIE 率、六维分差、硬检查失败率、耗时、成本 |
| 结论 | 支持/不支持假设、限制、下一步和签收人 |

### 4.3 判定规则

- 胜率点估计不是充分证据，必须同时报告置信区间和有效样本量。
- 若显著性成立但硬检查失败率上升、成本不可接受或出现授权风险，结论仍为不放行。
- 离线盲测胜率只证明离线偏好，不自动证明 WeCraft 生产端点击、阅读、转化或留存提升。
- 生产端效果必须在 WeCraft 做受控灰度或 A/B，并以生产指标单独验收。
