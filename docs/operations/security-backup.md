# 安全、审计与备份

## 身份与会话

- 邮箱密码使用 bcrypt 哈希；会话 token 只以哈希形式落库。
- `dt_session` 为 HttpOnly Cookie；生产必须启用 Secure 并置于 HTTPS。
- 会话、成员关系和角色每次请求从数据库重建，前端角色字段不参与授权。
- 邀请 token 一次性、有过期时间；已有账号接受邀请必须使用原密码。

## 权限

- RBAC 在服务端通过 `assertCapability` 执行。
- 只有 OWNER/DESIGN_LEAD 可以修改案例或反例授权。
- 只有 OWNER/ADMIN/DESIGN_LEAD 可以导出数据集。
- VIEWER 只能查看 ELIGIBLE 案例，不能读审计、修改授权或导出。
- 跨 Workspace 查询统一返回 404，避免泄露资源存在性。
- Holdout Brief、案例、反例、候选、含 Holdout 条目的数据集、关联任务和文件只对 OWNER/ADMIN 可见。

## 授权与数据使用

- 授权默认全部为 `false`，必须显式开启。
- 六项授权：可生成、可展示、可训练、可评测、可提炼机制、可公开展示。
- 数据集校验和导出使用授权快照；导出前再次检查授权漂移。
- 训练集检查 `canUseForTraining`；评测集检查 `canUseForEvaluation`。
- 任何授权变更写 `AuthorizationEvent` 与 `AuditLog`，要求填写理由。

## 评审完整性

- 提交后的 Review 不可原地更新；重复提交返回 409。
- 修订生成新版本，旧版本标记 `SUPERSEDED`，记录 `supersedesId` 和 `REVIEW_REVISED` 审计。
- 双评未全部提交前，案例评审接口隐藏他人分数；盲测接口不返回他人比较。
- 盲测 GET 不暴露模型、来源、上一轮分数；实验关闭后才返回候选映射。

## HTML 与文件安全

- 服务端使用 `sanitize-html` 白名单清洗；删除脚本、事件属性、表单、iframe、对象嵌入、外链和外部 CSS。
- 预览 iframe 使用 `sandbox=""`，不授予脚本或同源权限。
- 文件响应带 CSP：默认拒绝、脚本禁止、连接禁止、表单禁止；图片仅允许 data URI。
- 文件读取校验 Workspace、`deletedAt` 和关联主体权限；数据集 ZIP 不允许从通用文件接口直读，只能走带下载审计的导出接口。
- 截图限制 PNG/JPEG/WebP/SVG、8 MB，并读取真实尺寸；只接受 375px 或 750px 宽。

## 审计

记录登录、邀请、成员角色变更、Brief/案例/反例/候选创建与发布、授权变更、评审提交/修订、盲测提交、裁决、数据集校验/批准/导出/下载、实验创建/关闭。

每条审计包含：操作人、动作、资源、前后值、理由、请求 ID、IP、User-Agent、时间、`prevHash` 与 `entryHash`。追加时按 Workspace 获取 PostgreSQL 事务级 advisory lock，避免并发写入产生分叉哈希链。`entryHash` 使用数据库落库的同一 `occurredAt` 计算；可按 `id ASC` 复算完整链条，自动化测试已覆盖。

生产建议把审计日志每日导出到 WORM 存储或 SIEM；数据库账号不得拥有删除审计表权限。

## 备份

### 数据库

- 每日 `pg_dump -Fc` 全量备份，保留 30 天；关键发布前额外备份。
- 托管 PostgreSQL 开启 PITR/WAL 归档，RPO 建议不超过 15 分钟。
- 每季度至少一次从备份恢复到隔离环境，并运行只读校验。

### 对象存储 / 本地卷

- 每日快照或跨 AZ 复制；截图、HTML、数据集 ZIP 与数据库备份分开保存。
- 开启版本控制与对象锁；删除保留期建议 30 天。
- 恢复时必须同时恢复数据库与对象存储，避免对象键存在但文件缺失。

### 密钥

- 数据库密码、对象存储密钥、飞书凭据存入密钥管理。
- 数据库与第三方凭据每 90 天轮换或按安全事件立即轮换；停用账号后立即删除其 Session 记录。
- 离职成员立即停用账号并撤销会话；审计日志保留。

## 保留与删除

- 案例、评审、授权证据、审计按项目周期长期保留。
- 数据集 ZIP 为临时导出，15 分钟下载有效；对象可在 7 天后清理。
- 法律冻结生效时阻止相关数据删除与数据集导出。
- 删除用户内容前先检查授权、审计和法务保留要求。

## 事件响应

1. 立即停用受影响账号、撤销会话、轮换密钥。
2. 保全数据库审计、对象访问日志和代理日志。
3. 确认受影响 Workspace、案例授权和导出记录。
4. 按组织流程通知负责人；必要时暂停数据集导出。
5. 修复后补回归测试，并在测试报告记录。
