## 1. 结论

### 1.1 v1.0 要解决的问题

把分散在飞书、设计稿和人工表格里的设计案例，变成可评审、可授权、可盲测、可导出、可审计的结构化资产。平台不是“文件网盘”，而是设计训练数据的生产线。

### 1.2 MVP 做什么

- 飞书 OAuth 优先 + 邮箱邀请降级；Workspace、成员、角色、项目隔离。
- Brief 的创建、编辑、版本、dev/holdout 标记和黄金 brief 的评估依据。
- 优质案例与反例的独立对象：案例卡、授权、资产、机制标签、六维评分、证据。
- 标注/评审任务：分配、待办、独立评分、分歧裁决、不可变修订。
- 候选设计上传/API 写入、模型信息记录、硬检查、安全预览。
- 盲测房间：随机 A/B、隐藏来源/模型/历史分数、六维评分、偏好/平票。
- 仪表盘：主型覆盖、授权完整度、评审完成度、评审一致性、硬失败率、盲测胜率。
- 数据集：筛选、授权校验、版本快照、JSONL/CSV 导出、审计。
- 通知中心、飞书通知适配、审计日志、软删除/恢复/法律冻结占位。

### 1.3 MVP 不做什么

- 不训练模型、不推理、不微调、不部署模型；不把“平台操作”当成“模型训练”。
- 不替代飞书文档、IM、会议；平台只保存结构化字段和深链。
- 不做外部客户/自由设计师的开放门户。
- 不做移动端编辑；只保证 375px 设计截图预览。
- 不自动评分、不自动裁决、不自动生成评审意见。
- 不做 Elo/Bradley–Terry、实时协同、DAM、图片编辑器。
- 不做 SSO/SAML/SCIM、计费、公开 API 市场。
- 不修改 WeCraft 生产代码、数据库或发布流程。

### 1.4 三个最大风险

| 风险 | 具体表现 | 必须的兜底 |
| --- | --- | --- |
| R1 授权不可证明 | 案例/截图可用但缺授权证据；评测与训练授权混用；撤回后仍导出 | 六授权独立、训练/评测分离、证据门禁、撤回隔离、导出快照、不可声称可删除模型影响 |
| R2 评审噪声与泄漏 | 评分主观、无证据、盲测泄漏模型/来源、平票被强行算胜负 | 1–5 整数、证据锚点、双评+裁决、A/B 随机、白名单 DTO、TIE 保留不进入 DPO |
| R3 范围与数据生产拖期 | 60 brief/30 案例/10 反例与 6 周工程并行；飞书审批与法务口径不确定 | P0 只做安全闭环；飞书降级；数据周与工程周分离；W7 数据门禁不满足则不上线 |

### 1.5 上线必须同时满足

1. P0 流程全部可用，阻塞缺陷为 0。
2. 60 个 brief、至少 30 个案例、至少 10 个反例已导入。
3. Viewer、Annotator、Design Lead、Owner 四种角色权限测试通过。
4. 授权检查、审计日志、备份恢复测试通过。
5. 关键流程有自动化测试；承接方提供演示账号、README、部署说明。
6. 数据导出仅限 Owner/Admin/Design Lead。

## 2. 目标与非目标

### 2.1 目标

| 目标 | 可验收结果 |
| --- | --- |
| 结构化案例生产 | 30–36 个优质案例、10–12 个反例、60 个黄金 brief 可在平台内完成登记、评审、授权和导出准备 |
| 评审可追溯 | 每条评分有证据；两人独立评分；分歧有裁决；提交后修订生成新版本 |
| 盲测可信 | 每个 pair 默认 2 评 + 1 裁决；模型/来源/历史分数在提交前不可见；TIE 可保留但不算 DPO |
| 数据可导出 | 训练集/评测集按指定 JSONL 结构导出；授权不完整时无法导出；manifest 可复现 |
| 运营可审计 | 授权变更、状态变更、评审修订、导出/下载、法律冻结均可追溯 |
| 非技术可用 | 设计与编辑无需工程协助即可完成案例录入、提交评审和盲测打分 |

### 2.2 非目标

- 不是员工培训系统。
- 不是模型训练平台或推理网关。
- 不是飞书文档的替代品。
- 不是公开作品集或客户协作门户。
- 不是素材管理系统（DAM）或设计编辑器。

| 内容负责人 | `CONTENT_LEAD` | 黄金 brief 审批、内容事实与可发布性裁决 |
| 内容/编辑 | `EDITOR` | Brief、黄金 brief 创建与维护、内容证据 |
| 标注/QA | `ANNOTATOR` | 案例录入、标注、独立评审、QA、数据集校验 |
| AI 工程 | `AI_ENGINEER` | 候选上传/API 写入、硬检查、实验、模型信息 |

### 4.3 P2：规模化

这些能力要么依赖更大数据量/外部协作，要么会改变评审或排名口径，因此不进入 P0 安全闭环：AI 辅助标注、语义检索、Elo/Bradley–Terry、外部评审门户、实时协同、可视化 diff、数据血缘图、细粒度字段权限、SSO/SCIM、公开 API/Webhook、模型训练集成、DAM/设计编辑、计费。P2 的前提是 P0/P1 稳定、数据量足够、规则已确认。

## 5. 三条核心用户旅程

### 5.1 旅程 A：案例入库与双评

1. Editor 创建 Brief，填写正文、图片、目标读者、设计委托、品牌要求、禁止项、dev/holdout；黄金 brief 由 Design Lead + Owner 平台批准，Content Lead 的 W1 内容签收作为项目数据门禁证据。
2. Design Lead/Annotator 创建案例或反例，上传 375px 截图、桌面截图、HTML，填写机制、适用条件、反模式。
3. 填写六授权，上传证据；Owner/Design Lead 验证训练和评测授权。
4. 提交案例；系统执行硬失败/完整性检查，创建两名独立评审任务。
5. 两名评审各自提交 1–5 整数评分、结论和证据锚点；系统比较评分与结论。
6. 一致则进入批准；分歧则创建裁决任务。裁决人查看双方评分/证据，给出结论，不改写原评审。
7. 结果进入仪表盘；任何未解决分歧不得发布，也不得进入正式训练集。

**异常**：缺授权、缺 375px、HTML 危险、硬失败、作者自评、评审超时、授权撤回、评审提交后修订。全部按 `data-model.md` 状态机和 `acceptance.md` 用例处理。

### 5.2 旅程 B：候选提交与盲测

1. AI Engineer 通过页面或 API 提交候选 HTML/截图，记录模型供应商、名称、版本、实验。
2. 系统固化候选版本，执行 18 条硬检查；任一阻断失败则 `HARD_CHECK_FAILED`，不得进盲测。
3. 修复后生成新版本重跑；同一版本最多自动修复 2 轮。
4. Design Lead 冻结实验、生成 pair；每个 pair 默认 2 评 + 1 裁决，高价值 3 评。
5. 评审进入盲测房间：随机 A/B，隐藏模型/来源/历史/他人分数；对 A/B 各打六维整数分，选择偏好/TIE，附理由。
6. 两名评审提交并锁定后，只向裁决人揭示模型/来源；整批结束才向团队展示聚合结果和匿名来源。
7. 结果用于仪表盘；TIE 不进 DPO，但作为“无偏好”样本保留。

### 5.3 旅程 C：数据集导出

1. Owner/Design Lead 创建训练集或评测集，选择筛选条件、split、格式。
2. 系统逐项校验：训练集 `canUseForTraining`；评测集 `canUseForEvaluation`；证据有效；案例已批准；评审分歧已解决；资产安全；375px 可渲染。
3. 任一缺项 → `BLOCKED`，列出对象、缺项、证据、影响，禁止审批/导出。
4. 通过后生成 `manifest.json`、`briefs.jsonl`、`cases.jsonl`、`candidates.jsonl`、`preferences.jsonl`、`assets/`，冻结版本和授权快照。
5. Owner/Admin/Design Lead 下载 10 分钟签名链接；记录导出人、时间、IP、hash、条目数、排除项。
6. 撤回授权/法律冻结时：立即撤销未下载链接、隔离相关条目、标记影响范围；已交付版本不静默改写。

## 6. 信息架构与页面清单

### 6.3 交互约束

- 桌面优先，1280px 起；375px 截图支持适应宽度、100%、并排对比。
- 盲测刷新不改变 A/B 顺序；A/B 顺序按评审随机。
- 评分控件只允许 1–5 整数；N/A 只在无图片时可用。
- 评审提交前不显示他人分数；提交后不可原地编辑。
- 长表单自动保存草稿，但提交/导出必须显式动作。

## 7. 指标口径

| 指标 | 定义 | 计算 |
| --- | --- | --- |
| 主型覆盖 | 9 个主型下已批准案例数 / 目标 | 按主型统计；目标 36、最少 30；每型至少 3；显示缺口 |
| 授权完整度 | 已批准案例中六项授权均已明确、所需证据有效且未撤回的比例 | 分子：六字段均为明确 true/false；为 true 的字段有 VERIFIED 证据、未过期、未撤回；分母：已批准案例 |
| 评审完成度 | 已完成双评或裁决的案例/候选比例 | 有效评审 ≥2 或裁决完成；分歧未解决不计完成 |
| 评审一致性 | 两名评审结论和分数的接近程度 | 可发布结论一致率；各维平均绝对差；样本不足显示“样本不足”；TBD-CONSISTENCY 可替换高级统计 |
| 硬失败率 | 候选最新硬检查 run 存在阻断失败的比例 | 分子：最新 run 有 `BLOCK/FAIL` 的候选；分母：周期内有已完成 run 的候选；重跑不重复计分母 |
| 盲测胜率 | 候选在有效偏好比较中的胜负比 | `wins/(wins+losses)`；TIE 单独显示且不进 DPO，目标 TIE 率 <15%；显示 n 和 95% Wilson 区间 |
| 数据准备度 | 可进入目标数据集的高质量条目占目标量的比例 | 分子：已批准、授权完整、无未解决分歧、无 BLOCK 的案例/反例/黄金 brief；分母：30/10/60；显示缺口与阻断原因 |

**评分汇总**：六维等权 1/6，仅仪表盘诊断；缺图时图像叙事 N/A，剩余维度等权重归一化；不把汇总分作为准入总分。
