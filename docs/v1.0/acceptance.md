# WeCraft 设计训练协作平台 验收标准 v1.0

> 状态：冻结候选。验收以可复现步骤、明确期望和审计证据为准；不接受“页面能打开”作为完成。

## 0. 结论

- 13 条 E2E 覆盖案例入库、双评/裁决、候选/硬检查、盲测/TIE、数据集/导出、撤回/冻结、飞书降级、权限泄漏和备份。
- 上线必须同时满足 14 项门禁；S0/S1 未关闭不得以“试点”名义上线。
- 数据量、授权完整度、四角色权限、盲测无泄漏、备份恢复是可独立复核的硬门槛。
- 非技术设计/编辑的任务成功率和 375px 预览是可用性门槛，不由工程自测替代。

## 1. 验收基线

| 项目 | 基线 |
| --- | --- |
| 测试数据 | 60 个黄金 brief（30% holdout）、30 个优质案例、10 个反例、至少 20 个候选、8 个完成实验、5 个数据集 |
| 角色 | OWNER、ADMIN、DESIGN_LEAD、CONTENT_LEAD、EDITOR、ANNOTATOR、AI_ENGINEER、VIEWER |
| 必测角色 | VIEWER、ANNOTATOR、DESIGN_LEAD、OWNER |
| 浏览器 | Chrome/Edge 最近两个稳定版本；桌面 1280×800 起 |
| 视口 | 1280px、1440px；375px 设计截图预览 |
| 环境 | 预发环境，独立数据库/对象存储，不得连生产 WeCraft |
| 证据 | 每个 E2E 保留截图、请求 ID、审计记录、导出文件 hash |

## 3. 详细用例

### E2E-01 Brief、黄金 brief 与 holdout

**前置**：Workspace 已建；EDITOR 已登录；存在 9 个主型配置。

**步骤**

1. EDITOR 创建普通 Brief，填写正文、图片、目标读者、设计委托、品牌要求、禁止项，标记 `DEV`。
2. 创建 `GOLDEN_EVAL` Brief，只填标题，提交。
3. 补齐 `userIntent`、`hardConstraints`、`acceptableArchetypes`、`mustAvoid`、`referenceCaseIds`、1–3 份 `humanReference`、`rubricTargets`、`acceptanceNotes`，标记 `HOLDOUT`。
4. 提交；DESIGN_LEAD + OWNER 平台批准；CONTENT_LEAD 提供 W1 内容签收证据。
5. 修改已批准 Brief 正文，保存为新版本；检查旧版本仍可读。
6. 导入 60 个 brief，计算 holdout 比例；尝试把比例改成 20%。

**期望**

- 第 2 步返回 `VALIDATION_ERROR`，列出缺失字段，不创建可提交版本。
- 黄金 brief 通过后状态为 `READY`，版本不可原地覆盖；新版本回到 `DRAFT/READY` 并需重新签收。
- 旧版本内容、签收人、时间、hash 不变。
- holdout 接近 30%（按项目确认容差），20% 被拒绝并显示当前比例与差额。
- 所有批准/签收写审计；平台批准人为 DESIGN_LEAD + OWNER；W1 数据门禁至少有 CONTENT_LEAD + OWNER 签字证据。

### E2E-02 案例入库与双评

**前置**：已有已批准 Brief；ANNOTATOR A 创建案例；ANNOTATOR B、DESIGN_LEAD C 可评审；授权证据已上传。

**步骤**

1. A 创建案例，填写适用条件、设计机制、机制标签、反模式、来源、六维自评。
2. 上传 375×? 截图、桌面截图、HTML；HTML 含 `<script>` 和外部图片，先预览。
3. 填写六项授权，默认全 false；上传授权证据；DESIGN_LEAD 核验后将 `canDeriveMechanism/canUseForGeneration/canUseForDisplay/canUseForTraining/canUseForEvaluation` 置 true，`canShowPublicly` 保持 false。
4. 提交案例；分配 B 和 C 双评。
5. B 提交六维整数分、结论和截图区域证据；C 提交 HTML 片段证据；两人均通过。
6. 尝试让 A 评审自己的案例；尝试提交无证据评审；尝试原地修改已提交评审。

**期望**

- 第 2 步预览不执行脚本、不发外部请求；危险 HTML 返回 `HTML_UNSAFE`，不能提交。
- 授权创建时全 false；训练/评测授权只有 OWNER/DESIGN_LEAD 能改；ADMIN 修改返回 `FORBIDDEN`。
- 双评均通过、三维 ≥4、其余 ≥3、六授权证据完整、375 可渲染后，案例可 `APPROVED`。
- A 自评被拒绝；无证据提交返回 `VALIDATION_ERROR`；原地修改返回 `409 INVALID_STATE`，修订生成 v2 且旧版 `SUPERSEDED`。
- 批准后覆盖计数 +1，案例出现在已批准列表；审计含提交、核验、批准、修订。

### E2E-03 分歧与裁决

**前置**：案例已双评，评审 B 与 C 在“视觉机制”差 2 分，且 B 认为可发布、C 认为不可发布。

**步骤**

1. 系统比较两份评审。
2. DESIGN_LEAD 接到裁决任务，查看双方评分、证据、快照；不修改原评审。
3. DESIGN_LEAD 作出“要求修改”结论，附证据；案例进入 `CHANGES_REQUESTED`。
4. 作者提交新版本；重新双评；仍有分歧，进入第二次裁决。
5. 对裁决结果申诉一次；OWNER 复核并给出最终结论。
6. 模拟授权/隐私争议，检查 SLA 与裁决角色。

**期望**

- 任一维差 ≥2 或结论相反即 `ARBITRATION`；未裁决前案例不得 `APPROVED`，不得进正式训练集。
- 裁决记录触发原因、双方证据、裁决人、结论、规则影响；原评审不被覆盖。
- 常规设计争议 1 个工作日内裁决；授权/法律争议 3 个工作日内；超时显示阻塞并由 OWNER 决定。
- 同一争议最多申诉一次；最终结论由 OWNER 确认；全程审计。

### E2E-04 候选与 18 条硬检查

**前置**：实验 `DRAFT`；AI_ENGINEER 已提交候选 v1；规则集 `RULESET-TEST-1` 生效。

**步骤**

1. 候选 HTML 设置固定宽度 420px，提交硬检查。
2. 查看 `HC-03` 结果与 18 条规则登记。
3. 修复为 375px 自适应，创建 v2，重跑。
4. 对 v1 的误报申请例外，设置 24 小时有效期；到期后再看。
5. 对 v1 的 `HC-03` 在 1 个工作日内申诉；再由 DESIGN_LEAD + AI 工程在 2 个工作日内裁决；模拟超窗和重复申诉。
6. 让同一版本连续自动修复 3 轮。
7. 更新规则集版本，重跑 v2。

**期望**

- v1 `HC-03` 为 `BLOCK/FAIL`，候选 `HARD_CHECK_FAILED`，不能加入 pair。
- 18 条规则均有 rule ID、版本、严重级别、owner；技术规则有结果，治理规则有快照。
- v2 生成新 run，v1 结果保留；不得覆盖旧结果。
- 例外不修改原始 `FAIL`，只在有效期内改变门禁；到期自动失效并审计。
- 申诉超窗返回 `INVALID_STATE`；裁决只允许一次，结论 `UPHELD/OVERTURNED` 均审计；不得静默改原始结果。
- 同版本第 3 轮自动修复被拒绝，提示回退安全族（TBD-AUTOFIX 未确认时保持失败，由人修复）。
- 新规则集版本只对新 run 生效，历史 run 仍按原版本解释。

### E2E-05 盲测双评与揭示

**前置**：实验含 1 个 Brief、2 个已通过硬检查的候选；评审 R1、R2，裁决人 J；实验 `FROZEN`。

**步骤**

1. 启动实验，分配 R1/R2 与 J。
2. R1 打开盲测房间，记录 A/B 顺序；刷新页面。
3. R2 打开同一 pair，记录 A/B 顺序。
4. 两人分别提交六维分和偏好；提交前检查网络响应、HTML 注释、文件名、EXIF、错误信息。
5. R1 提交后尝试查看 R2 分数；J 在双锁前尝试揭示。
6. 双锁后 J 揭示模型/来源；整批关闭后查看团队聚合。

**期望**

- R1 刷新顺序不变；R1/R2 的展示顺序可不同，但都映射到同一规范 pair。
- 提交前无候选 ID、编号、标题、模型版本、来源、历史分数、他人分数、规范左右。
- R1 提交后仍看不到 R2；J 双锁前 `BLIND_METADATA_FORBIDDEN`，双锁后可看双方证据与模型/来源。
- 整批关闭前团队只看到进度；关闭后看到胜率、n、95% Wilson 区间、TIE 率和匿名来源。
- 评审人不能评审自己的候选；违规分配被拒绝。

### E2E-06 TIE 保留但不进 DPO

**前置**：盲测 pair 双评均认为方案相当。

**步骤**

1. R1 选择 `TIE`，不填理由，提交。
2. 补理由后提交。
3. R2 也提交 `TIE` 并写理由。
4. 关闭实验，创建偏好数据集并导出。
5. 检查 `preferences.jsonl` 与统计页。

**期望**

- 无理由 TIE 返回 `VALIDATION_ERROR`；有理由可提交。
- TIE 计入 TIE 率与“无偏好”统计，不进入 `preferences.jsonl`，不作为 DPO/偏好训练样本。
- 偏好条目只包含 `LEFT/RIGHT` 的 chosen/rejected；TIE 不被强行转成胜负。
- 仪表盘同时显示有效偏好 n、TIE 数与 TIE 率，样本不足显示“样本不足”。

### E2E-07 训练/评测集分离与阻断

**前置**：存在 `canUseForTraining=true`、`canUseForEvaluation=false` 的案例；存在 holdout brief；存在未解决分歧案例。

**步骤**

1. 创建 `TRAIN` 数据集，加入 holdout brief 和仅评测授权案例。
2. 创建 `EVAL` 数据集，加入仅训练授权案例。
3. 加入未解决分歧案例和无证据评审案例。
4. 查看阻断项，逐项修复后重新校验。
5. 用 CSV 作为训练源尝试导出。

**期望**

- TRAIN 拒绝 holdout 与仅评测授权条目；EVAL 拒绝仅训练授权条目；错误码 `DATASET_BLOCKED` 或 `AUTHORIZATION_INCOMPLETE`。
- 未解决分歧、无证据、未批准、硬失败、法律冻结均列为阻断项，显示对象、原因、责任角色。
- 修复后 `VALIDATING → READY_FOR_APPROVAL`；历史阻断记录保留。
- CSV 仅可导出人工汇总，不能作为训练源；`WECRAFT_V1` 才可训练/评测。

### E2E-08 数据集导出与审计

**前置**：数据集 `APPROVED`，含 500 条条目，授权完整，无法律冻结。

**步骤**

1. OWNER 发起导出，记录 `Idempotency-Key`。
2. 轮询状态至 `READY`；下载压缩包。
3. 解压检查固定文件：`manifest.json`、四个 JSONL、`assets/`。
4. 校验 manifest 的 `dataset_id/version/schema_version/created_at/created_by/rights_snapshot/item_count/content_hash`。
5. 用同一 key 重复发起；用 ADMIN 下载；用 ANNOTATOR 下载。
6. 等待下载链接过期后再下载。

**期望**

- 500 条导出在 10 分钟内完成；文件 hash 与 manifest 一致。
- `briefs.jsonl`、`cases.jsonl`、`candidates.jsonl`、`preferences.jsonl` 行数与 `item_count` 一致；资产路径存在且 hash 匹配。
- 同 key 返回同一任务，不重复打包。
- ADMIN 可下载但审计显示其不是授权修改人；ANNOTATOR 返回 `403`。
- 过期链接返回 `410/403`，不得泄露对象存储直链；下载写审计。

### E2E-09 授权撤回与隔离

**前置**：案例已批准并进入 TRAIN 数据集与一个已导出包；`canUseForTraining=true`。

**步骤**

1. DESIGN_LEAD 撤回训练授权，填理由与影响范围。
2. 检查案例状态、数据集条目、已生成下载链接、候选来源引用。
3. 尝试重新导出同一数据集版本。
4. 查看用户提示与审计。
5. 再撤回 `canUseForDisplay`，检查案例状态与展示入口。

**期望**

- 仅撤回训练授权时，案例保持 `APPROVED` 但训练资格关闭；TRAIN 数据集/条目立即隔离；下载链接立即失效；评测/展示不受影响。
- 再撤回 `canUseForDisplay` 后，案例转 `QUARANTINED`，平台展示入口关闭；`canShowPublicly` 仍独立控制对外。
- 新导出被拒绝；已导出文件记录影响范围并通知接收人。
- 页面明确提示“可停止后续使用，但不能保证从已训练模型中移除影响”，不承诺完全删除。
- 审计记录撤回人、时间、理由、字段变化、影响对象；不等待 30 天软删除。

### E2E-10 法律冻结、软删除与恢复

**前置**：存在已批准案例与数据集；ADMIN 可申请冻结，OWNER 可批准。

**步骤**

1. ADMIN 对案例发起法律冻结；OWNER 批准。
2. 尝试软删除案例、导出数据集、撤回授权记录。
3. 解除冻结；软删除案例；30 天内恢复；检查物理清理任务。
4. 尝试删除审计、已提交评审、授权事件。

**期望**

- 冻结期间删除/导出返回 `423 LEGAL_HOLD_ACTIVE`；授权记录不可删除。
- 解除后软删除成功；恢复可用；30 天内不物理清理，之后按策略清理。
- 审计、评审、授权事件无法删除；应用账号无 DELETE 权限。
- 冻结/解除/删除/恢复均有操作人、原因、时间、范围。

### E2E-11 飞书降级与通知

**前置**：飞书应用未配置；邮箱域可用；站内通知开启。

**步骤**

1. 新用户通过管理员邀请 + 邮箱登录。
2. 分配评审任务；检查站内通知（邮件通知为 P1，不作为 P0 验收项）。
3. 配置测试飞书机器人，发送任务通知；检查消息内容。
4. 模拟飞书 500/超时；检查重试、去重、站内兜底。
5. 检查通知深链跳转与权限。

**期望**

- 飞书未配置不阻塞登录、邀请、任务、导出；站内通知可用。
- 飞书消息只含任务 ID + 深链，不含正文、截图、HTML、评分、模型信息。
- 失败重试有上限，按 `dedupe_key` 去重；最终失败不阻塞业务事务，站内通知仍可用。
- 深链落地校验 Workspace/角色；无权限返回 404/403，不泄露标题。

### E2E-12 权限与盲测泄漏

**前置**：两个 Workspace；四类必测角色账号；盲测进行中。

**步骤**

1. VIEWER 访问未批准案例、导出接口、写接口。
2. ANNOTATOR 创建案例并尝试批准自己的案例、导出。
3. DESIGN_LEAD 批准、裁决、改训练授权、导出。
4. OWNER 最终签收、批准法律冻结、停用最后 Owner。
5. 用 Workspace A 的会话访问 Workspace B 的资源 ID。
6. 对盲测响应、网络、文件名、EXIF、HTML 注释、错误信息做泄漏扫描。

**期望**

- VIEWER：未批准内容不可见；写/导出 `403`；直链 `404`。
- ANNOTATOR：可录入、可被分配评审；不能批准自己的案例、不能导出。
- DESIGN_LEAD：批准/裁决/授权/导出成功；不能删审计。
- OWNER：签收/冻结成功；最后 Owner 停用返回 `INVALID_STATE`。
- 跨 Workspace 一律 `404`；批量接口、导出参数、深链均不能绕过。
- 盲测无任何禁止字段；DTO 白名单、文件名、图片元数据、HTML 注释全部通过。

### E2E-13 备份与恢复

**前置**：预发环境有完整测试数据；备份任务可用；RPO/RTO 按 TBD-RPO-RTO 默认值。

**步骤**

1. 触发全量备份，记录时间点与校验和。
2. 在隔离环境恢复数据库与对象存储。
3. 校验案例、评审、授权、审计、数据集 manifest/hash。
4. 记录恢复耗时与丢失窗口。
5. 执行一次故障演练：删除测试对象存储前缀后恢复。

**期望**

- 默认 RPO ≤15 分钟、RTO ≤4 小时；实际值以确认后的 TBD 为准。
- 恢复后审计链连续；已提交评审、授权事件、数据集 hash 一致。
- 恢复环境不得连接生产；恢复操作双人确认并审计。
- 演练报告包含时间、负责人、校验结果、问题与整改。
