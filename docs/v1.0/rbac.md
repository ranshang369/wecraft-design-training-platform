# WeCraft 设计训练协作平台 权限模型 v1.0

> 状态：冻结候选。权限以默认拒绝、最小权限、职责分离为原则；与 `decision-record.md` 冲突时以决策记录为准。

## 1. 结论

- 采用 Workspace 级 RBAC + 资源级校验，角色不是全局超级权限。
- 8 个角色：`OWNER`、`ADMIN`、`DESIGN_LEAD`、`CONTENT_LEAD`、`EDITOR`、`ANNOTATOR`、`AI_ENGINEER`、`VIEWER`。
- 上线必测 4 个角色：`VIEWER`、`ANNOTATOR`、`DESIGN_LEAD`、`OWNER`；其余角色做集成权限测试，不缩减矩阵。
- 数据集导出仅 `OWNER`、`ADMIN`、`DESIGN_LEAD`；其中 `ADMIN` 不能修改 `canUseForTraining`/`canUseForEvaluation`。
- 案例/反例作者、候选提交人/生成者不得评审自己的对象；违反时返回 `FORBIDDEN` 并写审计。
- 盲测元数据按阶段和角色白名单披露；任何角色都不能在双评锁定前看到模型版本、案例来源、历史分数或他人分数。
- 跨 Workspace 访问统一返回 `404`，不泄露资源是否存在。

## 2. 角色定义

| 角色 | 代码 | 职责 | 不能做 |
| --- | --- | --- | --- |
| 项目负责人 | `OWNER` | 目标、配额、最终签收、训练/评测授权、导出、法律冻结批准、最后 Owner 保护 | 不能删除/停用最后一个 Owner；不能绕过审计 |
| 平台管理员 | `ADMIN` | 成员与角色、Workspace 配置、集成、备份、审计读取、导出 | 不改训练/评测授权；不批准案例；不裁决设计争议；不读取盲测未揭示元数据 |
| 设计负责人 | `DESIGN_LEAD` | 案例/反例批准、设计裁决、Rubric 与硬检查例外、训练/评测授权、导出 | 不能批准自己创建/参与设计的案例；不能删除审计 |
| 内容负责人 | `CONTENT_LEAD` | Brief 内容审批、黄金 brief 内容签收、内容事实/可发布性裁决 | 不改训练/评测授权；不导出数据集；不批准设计质量 |
| 内容/编辑 | `EDITOR` | 创建/编辑 Brief、图片与正文、黄金 brief 草稿 | 不批准 Brief；不创建案例卡；不导出；不评审盲测 |
| 标注/QA | `ANNOTATOR` | 案例/反例录入、标注、被分配的案例评审与盲测评审 | 不批准案例/反例；不改授权；不导出；不裁决 |
| AI 工程 | `AI_ENGINEER` | 候选提交/API 写入、硬检查、实验与 pair 管理、模型元数据、数据集草稿 | 不批准案例；不改训练/评测授权；不导出；不评审自己的候选 |
| 只读观察者 | `VIEWER` | 查看已批准案例、Brief、聚合仪表盘 | 不写任何业务数据；不看未批准内容、评审身份、审计、授权证据、导出 |

> 用户清单未单列 Designer。v1 由 `ANNOTATOR` 完成案例录入、`DESIGN_LEAD` 审核；是否单设 Designer 记 `TBD-DESIGNER-ROLE`，不改变数据模型。

说明：

- `ADMIN` 的 `W` 仅限平台与成员配置；对内容对象没有写权限，避免“管理员即内容审批人”。
- 同一用户拥有多个角色时取并集，但职责分离约束仍然生效（例如 Owner 兼 AI 工程也不能评审自己的候选）。
- `VIEWER` 只能看 `APPROVED` 且 `canUseForDisplay=true` 的案例/反例；公开字段不包含授权证据、评审人身份和内部备注。
- 黄金 brief 的平台批准人是 `DESIGN_LEAD + OWNER`；W1 的 `CONTENT_LEAD + OWNER` 是项目数据门禁签字，不替代平台批准字段。
- 对象 owner：优质案例 `DESIGN_LEAD`；反例 `ANNOTATOR`（QA）或 `AI_ENGINEER`；最终签收 `OWNER`。对象 owner 不自动获得批准权限。

## 5. 资源级规则

每个请求在角色校验后继续执行以下校验，任一失败即拒绝：

1. **同 Workspace**：资源 `workspace_id` 必须等于会话当前 Workspace；跨 Workspace 返回 `404`。
2. **对象存在且未删除**：软删除对象默认不可读写；恢复需要 `ADMIN/OWNER`。
3. **分配关系**：评审、裁决、盲测任务必须 `assignee_id = current_user`，且状态为 `ASSIGNED/IN_PROGRESS`。
4. **所有权/参与关系**：作者不能审批自己的案例；提交人/生成者不能评审自己的候选。
5. **利益冲突**：任务拒绝/裁决时可声明冲突；系统记录并替换评审，不将冲突任务计为完成。
6. **版本一致**：写操作携带 `If-Match`/`row_version`；版本不匹配返回 `VERSION_CONFLICT`。
7. **授权门禁**：读取训练/评测导出内容前重新检查授权，不依赖列表页缓存。
8. **法律冻结**：任何删除、导出、撤回、恢复操作先检查 `legal_holds`；命中返回 `LEGAL_HOLD_ACTIVE`。

## 6. 盲测字段级可见性

| 阶段 | 评审人可见 | 裁决人可见 | 团队/Viewer 可见 |
| --- | --- | --- | --- |
| 任务分配 | Brief 字段、A/B 脱敏预览、Rubric、截止时间 | 同评审人 | 不显示未关闭实验细节 |
| 评审提交前 | 仅 A/B 预览与六维控件；无候选 ID、编号、标题、模型、来源、历史分数、他人分数、展示侧映射 | 同评审人；不提前揭示 | 仅实验名称/进度 |
| 本人提交后、双评未锁 | 自己的锁定结果；不可改 | 仍不可揭示 | 仅进度 |
| 双评均锁定 | 仍不看他人分数/来源 | 可看双方分数、证据、模型/来源，用于裁决 | 仅进度 |
| 整批关闭后 | 聚合胜率/TIE 率；匿名来源 | 完整裁决记录 | 聚合结果 + 匿名来源；不显示评审人身份 |
| 数据集 | 不参与导出 | 不参与导出 | 偏好数据使用 `reviewer_pseudonym`，不含姓名/邮箱 |

服务端必须使用盲测 DTO 白名单，而不是“查全量后删字段”。禁止下发：`candidate_id`、`candidate_no`、`title`、`model_*`、`source_case_ids`、`generation_params`、历史 `pairwise_comparisons`、其他评审结果、原始 HTML 文件名、EXIF、HTML 注释中的模型信息。

## 7. 授权职责分离

| 动作 | 允许角色 | 额外要求 |
| --- | --- | --- |
| 新建授权记录 | OWNER、DESIGN_LEAD | 六字段默认 false；证据可后补但不得置 true |
| 修改 `canUseForTraining` | OWNER、DESIGN_LEAD | 证据 VERIFIED、理由、影响范围、审计 |
| 修改 `canUseForEvaluation` | OWNER、DESIGN_LEAD | 同上；与训练授权独立 |
| 修改其余四项授权 | OWNER、DESIGN_LEAD | 理由与审计；ADMIN 只读 |
| 核验证据 | OWNER、DESIGN_LEAD | 记录核验人/时间；不得自证自批 |
| 撤回授权 | OWNER、DESIGN_LEAD | 立即隔离；通知影响范围；不可撤销审计 |

`ADMIN` 可以导出已批准数据，但不能通过“先导出再改授权”绕过职责分离；导出前服务端重新检查授权快照。

## 8. 导出与下载

- 只有 `OWNER/ADMIN/DESIGN_LEAD` 可以创建导出任务、获取下载链接、重新下载。
- 下载链接短期有效（默认 15 分钟）、一次性或限次、绑定会话；不得放入邮件正文或飞书消息正文。
- 导出必须记录：导出人、时间、数据集版本、条目数、授权快照 hash、文件 hash、下载次数、IP/UA。
- `AI_ENGINEER` 可以准备数据集草稿，但不能批准或下载；`CONTENT_LEAD/EDITOR/ANNOTATOR/VIEWER` 均不可导出。
- 已撤回/过期/法律冻结的数据集，下载链接立即失效；已下载文件无法追回时记录影响并通知安全负责人。

## 9. 审计、破窗与法律冻结

### 9.1 审计

- 审计只追加；`OWNER/ADMIN` 可读全量，`DESIGN_LEAD/CONTENT_LEAD` 读本 Workspace 业务范围，其他角色只读自己的动作。
- 审计导出本身是高风险动作，仅 `OWNER/ADMIN`，并再次写审计。
- 审计中的邮箱、IP、授权证据路径按最小必要脱敏；法务/安全需要时走审批。

### 9.2 破窗（Break-glass）

- 仅用于账号恢复、生产事故、法务保全；不用于绕过盲测或授权门禁。
- 必须 `OWNER + ADMIN` 双人发起，填写原因、范围、时限（默认 ≤24 小时），自动通知安全负责人。
- 破窗权限只读或修复账号，不授予导出、授权修改、盲测揭示；所有操作强制审计。
- 到期自动回收；延期需重新审批。

### 9.3 法律冻结

- `OWNER` 批准/解除；`ADMIN/DESIGN_LEAD` 可申请；法务可要求。
- 冻结范围内禁止删除、物理清理、导出、撤回授权记录；允许读取和必要的保全复制。
- 解除后不自动恢复导出，需重新校验授权与数据集状态。

## 10. API Token 权限

| Scope | 允许 | 不允许 |
| --- | --- | --- |
| `candidate:write` | 创建候选、上传 HTML/截图、提交硬检查 | 读取评审、修改授权、导出 |
| `hardcheck:read` | 读取自己候选的硬检查结果 | 读取他人候选 |
| `experiment:read` | 读取自己参与的实验元数据 | 读取盲测个人比较、模型映射 |
| `dataset:read` | 读取数据集元数据与阻断原因 | 下载导出包、批准、修改授权 |

Token 绑定 Workspace、创建人、过期时间；明文只显示一次；默认 90 天过期；撤销立即生效。Token 不得拥有 `OWNER` 能力。

| 编号 | 角色 | 场景 | 期望 |
| --- | --- | --- | --- |
| RB-01 | VIEWER | 打开未批准案例、导出、调用写接口 | 列表不出现；直链 `404`；写接口 `403` |
| RB-02 | ANNOTATOR | 创建案例并提交；被分配评审 | 可创建；不能批准自己的案例；不能导出 |

## 12. 默认拒绝清单

- 未明确授予的角色能力一律拒绝。
- 未分配、未接受、已过期任务不可提交评审。
- `ADMIN` 不得读取盲测未揭示映射、不得修改训练/评测授权、不得批准案例。
- 任何角色不得删除审计、授权事件、已提交评审、已批准数据集快照。
- 任何角色不得通过前端字段、URL、导出参数或 API 批量接口绕过 Workspace 边界。
